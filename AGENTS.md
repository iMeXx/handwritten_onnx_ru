# AGENTS.md — inknet-hybrid

Инструкции для агентных помощников. Дорожная карта — `docs/PLAN.md`,
статус и точка входа — `README.md`.

## Контекст

Гибрид (вариант B): растровая CNN (`LineNet`) + **векторная ветка штрихов**
(TCN по кадрам ink-features), fuse перед общим BiLSTM+CTC. Проект
самостоятельный: свой скрипт датасета, свои vendor-копии портов, своё
обучение/оценка. Параллельно существует `../inknet-online` (вариант C,
вектор-нативная модель) — это НЕ зависимость, а сосед по эксперименту.

Связанные репозитории (не редактировать без явного запроса):

- `../inknet-online` — вектор-нативный baseline; общий формат датасета
  `inknet-line-vectors/3` и общий скрипт-билдер (байт-копия, контроль `make parity`);
- `../inknet-train` — эталон боевой растровой модели (архитектура продублирована
  в `hybridnet/vendor/linenet.py`);
- `jsnet/` — самодостаточный vendor-слой данных: эталонные JS-экстракторы
  (`jsnet/src/{ink-features,ink-mlp}.js`), снимок базы написаний (`jsnet/db/app.db`,
  обновляется копированием файла из сборочного приложения), `vocab`/`terms`.
  Переменная `WEB_ONNX` (=jsnet) — имя задано parity-зафиксированным билдером.
  В `jsnet/{server,public}` живёт и локальное веб-приложение (`make up`):
  тренировка эталонов, плановый сбор написаний, статистика датасета, распознавание
  строк (`/lines.html`: ONNX в Web Worker, WASM-only) — всё пишет
  в ту же `app.db`; вход — по имени автора, без паролей и регистрации (сессия —
  cookie `sid`); QC написаний — nearest-neighbor по `ink-features` (не ONNX);
  перо настраиваемое (кнопка «✒ Перо»), `js/{pen,settings,pensettings,capture}.js` —
  байтовые копии, правки на месте не делать (синхронизация `cp`); распознавание:
  `js/{ctc-decode,line-preprocess,dict}.js` и `js/vendor/onnxruntime/` — байтовые
  копии, а `js/{lines,line.worker}.js` — порты с адаптацией (shell-вход, локальный
  ort без WebGPU), пайплайн 1-в-1.

## Команды

```bash
make env              # эффективная конфигурация
make ds               # свой датасет векторных строк -> data/line-vectors/
make train            # один режим: MODE=fusion|vector|raster (.env MODE)
make eval             # CER+примеры по весам режима MODE
make ablation         # триада raster+vector+fusion на одних строках/сидах + вердикт
make compare          # вердикт по work/<mode>/summary.json (гейт M2)
make smoke            # ds+train+eval быстро (ARGS="--epochs 30")
make parity           # контроль: builder/vendor совпадают с inknet-online
make up               # веб-приложение jsnet фоном (демон): тренировка/сбор/статистика/распознавание
                      # (адрес в .env: WEB_HOST/WEB_PORT; down / status / log)
make merge            # снимок app.db -> data/db/app-merged.db, склейка логинов по людям
make ds-merged        # person-disjoint датасет из снимка -> data/line-vectors-m/
make ablation-merged  # триада по людям: merge + ds-merged + обучение + вердикт
                      # (train-merged / eval-merged / compare-merged / smoke-merged)
```

Разовые переопределения: `make train ARGS="--mode raster --runs 3"`.
Weights/метрики: `work/<mode>/fold<i>/model-best.pt`, `work/<mode>/summary.json`.

## Правила проекта

1. **Ablation обязателен**: цифра гибрида существует только в тройке
   raster-only / vector-only / fusion на одном writer-disjoint разрезе и на
   `RUNS>=3` сидах (`make ablation`).
2. **Критерии гейта M2**: −5% относительных CER к raster-only (проверяет
   `compare.py`); вес векторной ветки ≤ 1 МБ int8; graceful деградация при
   пустом векторном входе.
3. **Контракты клиента неприкосновенны**: blank=0, `line_vocab.json[i-1]`,
   `logits [B,T,C]`, STRIDE=10 семантика `VF`
   (`jsnet/src/ink-features.js` — vendor-копия, клиент векторы вычистил). Расширение алфавита = синхронная правка
   vocab + клиента + тренировщика.
4. **Vendor вместо зависимостей**: `hybridnet/vendor/{raster,linenet}.py` —
   копии из inknet-train/inknet-online. Правки клиента (препроцессинг полос) в порт
   растра заносятся вручную во ВСЕ копии; `make parity` ловит расхождение
   билдера и растра с inknet-online.
5. **Паритет представлений в тройке**: все три режима видят одни файлы
   `fold<i>.*.json`, фиксированное перо PEN_DEFAULTS (без вариации толщины),
   одни сиды (`SEED + 100*run + fold`). Выравнивание векторных кадров к
   растровым — линейная интерполяция по времени в `hmodel.forward` — обязана
   быть воспроизведена в экспорт-графе ONNX 1-в-1.
6. **Парity препроцессинга**: ассоциация штрихов с полосами на обучении и в
   воркере обязана давать идентичную нумерацию полос — тесты паритета до
   интеграции, не после.
7. Оценка только writer-disjoint (leave-one-writer-out), **и по людям, а не по логинам**:
   в `app.db` у одного человека по несколько аккаунтов (сдача с двух устройств), билдер
   группирует по `username` → фолды пересекаются по почерку. Группировка делается в снимке
   базы (`make merge` → `data/db/app-merged.db`, карта `scripts/writers-merge.json`), сам
   билдер не правится (правило 4, гейт `make parity`); обучение по людям — `*-merged` цели
   (`data/line-vectors-m/`, `work-merged/`).

## Известные грабли

- Родные проекты оставили следы ошибок: NaN→`null` в JSON, evaluate «против
  самой себя», вложенный spread typed-arrays, коррелирующие строки у
  mulberry32 на арифметических сидах. Правила в `../inknet-online/AGENTS.md`;
  переносить код — переносить и проверки.
- Векторная ветка на общем `LR=2e-3` не обучается вообще: CTC-коллапс к одной короткой
  гипотезе («сал»/«рн»), CER ~0.9 и на тесте, и на собственных обучающих авторах, loss в
  плато ~3.1. Та же архитектура на тех же строках при `LR_VECTOR=2e-4` даёт 0.27. Прежние
  выводы M1/M2 про «вектор не хуже растра» получены на подавленной конфигурации; vector
  требует отдельных `LR_VECTOR`/`EPOCHS_VECTOR` (на низком LR сходится на 300–400 эпохах).
- Малый объём данных даёт разброс CER ±0.15 на прогон — не сравнивать модели
  по одному обучению; сравнение fusion-vs-raster на 2 авторах незначимо.
- `Makefile` делает `export` всех переменных, поэтому `FOLD ?= 0` попадает в окружение
  каждого рецепта, а `train.py` берёт `--fold` из окружения: без явного `--fold`
  обучение молча идёт по ОДНОМУ фолду (гейт M2 при этом выглядит «зелёным»).
  Все цели обучения передают `--fold $(TRAIN_FOLD)` (`TRAIN_FOLD ?= all`) явно.
- Эпохи мерить не эпохами, а шагами: фолд на 600 строк — это в 2.5 раза меньше шагов
  в эпохе, чем фолд на 1500. На 60 эпохах CTC ещё не раскатан (CER ~0.9 при том, что
  на 130 эпохах тот же старт даёт 0.23–0.28), поэтому `smoke` не укорачивает эпохи.
- `collate`: паддинг растровой ширины брать по МАКСИМАЛЬНОЙ ширине штрихов
  (`ink.shape[1]`), а не по `4*max(img_lens)` — dw не кратен 4 и паддинг
  обрезает реальный растр (проверено ошибкой времени выполнения).
- В vector-режиме `ink=None`: любые обращения к растру в collate/метриках
  обязаны это учитывать.
- `COLLATE NOCASE` в SQLite складывает только латиницу: кириллические имена
  авторов «Инна»/«инна» — разные строки, и один почерк заводится двумя авторами,
  что ломает writer-disjoint. Имена сравниваем в JS (`findUserByName` в
  `jsnet/server/index.js`), а не `WHERE username = ?`.
- POST-тело в `jsnet/server/index.js` копится `Buffer`-чанками и декодируется
  один раз: строковая склейка (`body += chunk`) режет многобайтовый UTF-8 на
  границе чанка, символы превращаются в U+FFFD и большая сдача сессии с планшета
  отбивается с «некорректное написание» (клиент показывал «сервер не принял»).
- Chromium на Android в `getCoalescedEvents()` подмешивает pointer-события с
  NaN-координатами: экспоненциальный сглаживающий фильтр `capture.js` расползается
  NaN по всему штриху, `JSON.stringify` пишет `null` вместо чисел, и `validStrokes`
  отклоняет из-за одного написания ВЕСЬ батч `/api/train` (all-or-nothing →
  «сдано 0, остальное в буфере»). `pointercancel` (угон жеста браузером) оставлял
  штрих из 1 точки — контракт требует ≥2. Guard'ы: конечность координат в
  `_addPoint` и `≥2` в `finish` (`src/capture.js` — байтовая копия, синхронизация `cp`),
  санитизация пачки перед сдачей в `collect.js` (бракованные writing'и убираются
  из буфера со списком символов, а не глушат сдачу).
