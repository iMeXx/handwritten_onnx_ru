# Проект: inknet-hybrid — от «Варианта B» к сбору данных

**Статус (2026-11): направление гибрида закрыто, проект переориентирован на
сбор написаний + датасетный конвейер.** Модель распознавания — боевая растровая
`line_int8` (обитает и обучается в `../inknet-train`).

## 1. Итог эксперимента «Вариант B» (растр + векторная ветка штрихов)

Гипотеза: динамика письма (скорость, нажим, наклон, pen-up), теряемая при
растеризации, подтянет распознавание через векторную ветку (TCN по кадрам
ink-features), fuse перед общим BiLSTM+CTC.

Проверка — person-disjoint триада (5 человек, leave-one-writer-out, 3 сида на
режим, `make ablation-merged`):

| режим | CER (средн.) |
|---|---|
| raster (LineNet, 3.3M) | **0.454** |
| vector (VecLineNet, 0.7M) | 0.575 |
| fusion (HybridNet, 3.65M) | 0.657 |

Гейт M2 (−5% относительных CER у fusion над растром) **не покрыт**, причём гибрид
хуже и вектора, и растра. Отдельная проверка «вектор как второе мнение
пер-user» (сетка α-взвешивания логитов по авторам) дала α\* = 0 у всех авторов
(CER при α\* точь-в-точь растровая; oracle-α — сотые доли). Пробы вектора на
уровне букв (NN-зонд `glyphEmbedding`): кросс-авторский top-1 0.40–0.44 при
потолке внутри автора 0.55–0.63 — признаки не несут однозначно считываемой
буквы; основные путаницы — цифра ↔ курсивная буква (з↔3, т→4, ь→6, л→8).

**Вывод: `line_int8` — лучшее, что есть; векторная ветка к боевой модели
ничего не добавляет на текущих данных.** Код направления (модели, обучение,
экспорт, селектор гибрида в воркере) удалён из репозитория, артефакты триады
(`work-merged/{fusion,vector,fusion-baseline}`, логи) удалены; сохранён только
writer-disjoint бейзлайн растра `work-merged/raster/` — точка сравнения при
дообучении `line_int8`.

Урок на будущее (для `../inknet-online`): векторная ветка на LR=2e-3 не
обучается вовсе (CTC-коллапс к константе, CER ~0.9), требует LR=2e-4 и
300–400 эпох; выводы, полученные на подавленной конфигурации, невалидны.

## 2. Текущий план

1. **Сбор данных** (главный ограничитель: разброс CER ±0.15 на прогон):
   тренировка эталонов и плановый сбор написаний через jsnet (`make up`),
   новые авторы, покрытие путающих пар; QC nearest-neighbor по `ink-features`.
2. **Качество разрезов**: `make merge` (склейка логинов одного человека) +
   `make ds-merged` — всё оценивается только person-disjoint (правило 2 в
   AGENTS).
3. **Дообучение `line_int8`** — в `../inknet-train`: `--init work/model-best.pt`
   с низким LR (1e-4), контроль CER по своим авторам (забывание), новые данные
   через `--refs app.db` / `--inbox`; экспорт fp32 → int8 с проверкой
   паритета greedy.
4. **Доставка модели в веб-приложение**: `jsnet/public/models/line_int8.onnx`
   + `.ort`, `CACHE` в `jsnet/public/sw.js`; деплой — `docs/DEPLOY.md`.

## 3. Не-цели

- Обучение/переобучение векторной ветки и гибрида — без явного пересмотра
  решения владельцем модели.
- Серверный инференс: распознавание остаётся полностью на устройстве
  (решение принято, `jsnet` сервер в инференсе не участвует).
