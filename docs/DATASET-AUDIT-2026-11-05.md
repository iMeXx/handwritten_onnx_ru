## 2. Датасет на диске устарел

`data/line-vectors/manifest.json` описывает **2 автора** (iMeXx, owline) и 2 фолда — он собран
до волны сбора 2026-11-04. Нужен `make ds`. Весы в `work/<mode>/fold{0,1}` относятся к этому
устаревшему разрезу; сравнивать их с новыми прогонами нельзя.

Пересборка (параметры из `.env`: `LINES=150`, `TEST_LINES=30`, `MULTIWORD_PROB=0.4`) даёт:
**8 фолдов** leave-one-writer-out, по **1050 обучающих** строк (7 авторов × 150) и **30 тестовых**,
~220 кадров на строку, метка ~10 классов, кадров/метку ~21 (CTC-бюджет с запасом).

## 3. Обучаемость: да, данных хватает (пробные прогоны, фолд 0, тест = owline, 1 сид)

| режим | параметры | эпох / LR | writer-disjoint CER |
|---|---|---|---|
| raster (`LineNet`) | 3.3M | 40 / 2e-3 | 0.303 (на 40-й ещё падает) |
| raster (`LineNet`) | 3.3M | 120 / 2e-3 | **0.221** (обучающий loss 0.000) |
| vector (`VecLineNet`) | 0.7M | 400 / 2e-4 | **0.272** |
| vector (`VecLineNet`) | 0.7M | 600 / 5e-4 | 0.286 |
| fusion (`HybridNet`) | 3.65M | 60 / 2e-3 | **0.150** (обучающий loss 0.004) |

Для сравнения: на старом датасете из 2 авторов те же режимы давали 0.86–0.95 (коллапс к
коротким частотным строкам). То есть узким местом был объём данных, а не архитектура:
при 7 авторах в обучении растр учится и обобщает, гибрид лучше растра сильнее, чем требует
гейт M2 (−5% относительно), — на одном фолде и одном сиде.

**LR = 2e-3 из `.env` ломает векторную ветку**: с ним `VecLineNet` за 250 эпох не может
даже переобучиться на своих же авторах (CER 0.91 на train, гипотеза — константа «рн», loss
плато ~3.14). При 5e-4 уже CER 0.595, при 2e-4 — 0.272. Все прежние выводы про «вектор
не лучше/хуже растра» получены на подавленной конфигурации и пересматриваются.

## 4. Что портит оценку (по значимости)

1. **Дубли авторов.** Имена и метаданные сдачи указывают, что за 8 аккаунтами ~5 человек:
   пары `etel1`/`Etel2`, `Vika1`/`Vika2`, `Dima1`/`Dima2` сданы в один день с интервалом
   10–45 минут с РАЗНЫХ устройств (iPad и Huawei-планшет), пустые пары `owline`/`owline1`,
   `Ilana1`/`Ilana2`. Геометрия написаний в парах почти совпадает: etel1 42.7×64.7 пикселя
   и Etel2 45.9×64.5 (0.292 и 0.338 пикс/мс), Dima1 22.7×27.5 и Dima2 22.0×26.1
   (0.198 и 0.170). Подтвердить это по самим чернилам нельзя: `glyphEmbedding` авторов не
   различает (отношение межавторского разброса к внутриавторскому 1.00–1.23 для всех пар),
   то есть QC-инструмент для этого непригоден.
   Следствие: **6 из 8 фолдов протекают** по авторам (тест `Vika1` ↔ `Vika2` в обучении и т.п.);
   чистые — фолд 0 (`owline`) и фолд 7 (`Ilana2`). Все числа выше получены на чистом фолде 0.
2. **Выбор модели по тестовому срезу.** Ранний стоп и «лучший CER» считаются по тому же
   writer-disjoint тесту → систематически оптимистичная метрика.
3. **30 тестовых строк на фолд** (~40 слов): одиночный фолд даёт шум ±0.1 CER и более.
4. **Мёртвые каналы признаков.** В БД хранятся только `x,y,t`, поэтому `PRESS`, `TILT_X`,
   `TILT_Y` (индексы 6–7–8 в `VF`) постоянны: в `manifest.json` у них `sd = 1e-6`. Векторная
   ветка обучается на 7 признаках из 10, а клиент на serving эти каналы отдаёт — риск
   рассинхрона обучающего и боевого представления.
5. **Цифры в тесте без обучения.** В фолдах 2, 3, 5 встречаются классы `1`, `4`, `5`, `6`, `8`, `9`,
   которых нет в обучающих строках — это гарантированные ошибки CER.
6. Лексическая утечка мала: 10% слов теста уже встречаются в обучении того же фолда (31 из 324).

## 5. Стоимость полного ablation и как её сократить

Эпоха на 1050 строках: raster ~9 с, fusion ~17 с, vector ~1 с (RTX 5080, 16 ГБ; сейчас ~15 ГБ
занято сторонним процессом). Полная триада `8 фолдов × 3 сида × 300 эпох` ≈ 55–60 ч.
Реалистичный вариант: 5 чистых фолдов (по одному на человека), `RUNS=3`, `EPOCHS=150`,
`PATIENCE=40` → ~10–12 ч; `TEST_LINES` поднять до 100–150 (синтез бесплатный, дорожает только
оценка).

## 6. Что сделано (2026-11-05) и чек-лист дальше

Сделано (не трогая parity-артефакты, `make parity` зелёный):

- `scripts/merge-writers.mjs` + карта `scripts/writers-merge.json`: снимок `jsnet/db/app.db`
  → `data/db/app-merged.db`, логины одного человека склеены в одного автора
  (`owline, etel, vika, dima, ilana, imexx`). Исходная база не меняется, отчёт —
  `data/db/app-merged-merge.json`. Снятая с человека база = **5 авторов годны** к датасету;
- `make merge`, `make ds-merged` (→ `data/line-vectors-m/`, 5 фолдов, 600 обучающих и
  120 тестовых строк на фолд), `make ablation-merged`, `make train-merged`,
  `make eval-merged`, `make compare-merged`, `make smoke-merged`, `make clean-merge`;
- в `.env`: `LR_VECTOR=2e-4`, `EPOCHS_VECTOR=400`, `PATIENCE_VECTOR=120` — `ablation-merged`
  подставляет их для vector, raster/fusion учатся на `LR`;
- прогон гейта: `mkdir -p work-merged && nohup env PYTHONUNBUFFERED=1 make ablation-merged
  TEST_LINES=120 RUNS=3 > work-merged/ablation.log 2>&1 &` (5 фолдов × 3 сида × 3 режима;
  по замерам ~6 с/эпоха raster, ~2× медленнее fusion, ~0.5 с vector ⇒ ~10–14 ч на RTX 5080,
  GPU при этом занят ещё одной задачей);
- правка `Makefile`: `TRAIN_FOLD ?= all` и явный `--fold` во всех целях обучения. До этого
  `FOLD ?= 0` из-за `export` в начале файла попадал в окружение рецептов, а `train.py`
  читает `--fold` из окружения → `make ablation` учил ОДИН фолд, выдавая при этом «вердикт
  гейта» по одному автору (первый прогон это и показал: в summary был только фолд0).
