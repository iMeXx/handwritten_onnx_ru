# inknet-hybrid

Гибридная строчная модель: **растровая CNN + векторная ветка штрихов** с общим
CTC-хедом (Вариант B). Дорожная карта — в [docs/PLAN.md](docs/PLAN.md).

## Самостоятельный проект

Полный конвейер живёт здесь, параллельно с [inknet-online](../inknet-online)
пересечений нет (свои `data/` и `work/`, никаких кросс-записей):

| цель make | что делает |
|---|---|
| `make venv` | локальный `.venv`: torch CPU + `requirements.txt` (проект не привязан к внешним venv) |
| `make ds` | свой датасет `inknet-line-vectors/3` из снимка базы написаний `jsnet/db/app.db` (скрипт — байт-копия inknet-online, контроль `make parity`) |
| `make train` | обучение одного режима: `MODE=fusion\|vector\|raster` |
| `make eval` | CER по writer-disjoint фолдам + примеры ref→hyp |
| `make ablation` | **триада raster + vector + fusion** на одних строках/фолдах/сидах и вердикт гейта M2 |
| `make compare` | повторить вердикт по `work/<mode>/summary.json` |
| `make smoke` | ds+train+eval быстро (`ARGS="--epochs 30"`) |
| `make merge` | снимок базы `jsnet/db/app.db` → `data/db/app-merged.db` со склейкой логинов одного человека в одного автора (карта `scripts/writers-merge.json`) |
| `make ds-merged` | person-disjoint датасет из снимка → `data/line-vectors-m/` (фолды по людям) |
| `make ablation-merged` | `merge` + `ds-merged` + триада + вердикт на person-disjoint разрезе; для vector свои `LR_VECTOR`/`EPOCHS_VECTOR` |
| `make train-merged` · `eval-merged` · `compare-merged` · `smoke-merged` · `clean-merge` | те же шаги по одному; `smoke-merged` — быстрая проверка конвейера (1 фолд, 1 сид) |
| `make parity` | контроль синхронности общих артефактов с inknet-online (на машине без соседнего репозитория — skip) |
| `make up` / `make down` | поднять / остановить веб-приложение jsnet **фоном** (демоном); `make status`, `make log` |

## Установка на чистой машине

Нужен Python ≥ 3.10 (torch 2.14) и Node ≥ 23 — веб-приложение jsnet работает на
встроенном `node:sqlite` без npm-зависимостей.

```bash
git clone <remote> inknet-hybrid && cd inknet-hybrid
make venv              # .venv: torch CPU (с GPU-машины — PY= в .env, см. requirements.txt)
cp .env.example .env   # правки не нужны для локального прогона; сервер — в .env.example
make ds && make smoke ARGS="--epochs 30"   # конвейер: датасет → обучение → оценка
make up                # веб-приложение: http://127.0.0.1:3210 (make down / status / log)
```

`make parity` на машине без `../inknet-online` печатает skip — гейт живёт там,
где есть оба репозитория. Деплой на сервер (Ubuntu, systemd, nginx+TLS,
rsync-доставка кода, перенос базы) — [docs/DEPLOY.md](docs/DEPLOY.md).

## Триада по людям (person-disjoint) — как гонять

В `jsnet/db/app.db` у одного человека по несколько логинов (сдача с iPad и Android-планшета
в один день: `etel1`/`Etel2`, `Vika1`/`Vika2`, `Dima1`/`Dima2`), а билдер группирует
написания по `username` → writer-disjoint фолды пересекаются по людям (протекали 6 фолдов
из 8). Билдер править нельзя (гейт `make parity`), поэтому логины склеиваются в **снимке**
базы: `scripts/merge-writers.mjs` + карта `scripts/writers-merge.json` (её правят люди, когда
подтверждают, что аккаунты принадлежат одному почерку). Исходная база не изменяется,
`make parity` остаётся зелёным.

```bash
# полный прогон гейта M2: 5 человек × 3 сида × 3 режима (~10–14 ч на RTX 5080)
mkdir -p work-merged
nohup env PYTHONUNBUFFERED=1 make ablation-merged TEST_LINES=120 RUNS=3 > work-merged/ablation.log 2>&1 &
tail -f work-merged/ablation.log      # ход обучения и вердикт в конце
make compare-merged                   # вердикт по work-merged/<mode>/summary.json

# быстро посмотреть, что конвейер живой (1 фолд, 1 сид, ~1 ч)
make smoke-merged

# один режим поверх готового person-disjoint датасета
make train-merged MODE=vector ARGS="--fold 0"
make eval-merged  MODE=vector ARGS="--fold 0"
```

`TEST_LINES=120` вместо 30: на 30 тестовых строках шум ±0.1 CER; синтез строк бесплатный,
дорожает только оценка. Векторную ветку нельзя учить на общем `LR=2e-3` — она коллапсирует
к константе (CER ~0.9 даже на своих авторах), поэтому `ablation-merged` подставляет
`LR_VECTOR=2e-4` и `EPOCHS_VECTOR=400`. Все цели обучения явно передают `--fold $(TRAIN_FOLD)`
(`all`): из-за `export` в начале `Makefile` переменная `FOLD=0` иначе попадает в окружение
`train.py` и обучение молча идёт по одному фолду. Разбор данных и обучаемости —
[docs/DATASET-AUDIT-2026-11-05.md](docs/DATASET-AUDIT-2026-11-05.md).

Модели: `raster` — vendor-копия боевой `LineNet` (3.3M); `vector` —
`VecLineNet` как в inknet-online (~0.7M); `fusion` — `HybridNet`: тот же растр
+ TCN-ветка штрихов, векторные кадры интерполируются к растровым по времени и
склеиваются перед общим BiLSTM+CTC (+0.35M параметров). Контракт клиента
сохранён во всех режимах: blank=0, `line_vocab.json[i-1]`, `logits [B,T,C]`.

## Статус: ablation-триада на M1-данных (2026-11-02)

Данные те же, что в inknet-online: 2 автора, 1 написание на букву, датасет v3
(двухсловные строки с пробелом). Оценка — 3 сида на режим, один и тот же
writer-disjoint разрез:

| фолд | тест-автор | raster (3.3M) | vector (0.7M) | fusion (3.65M) |
|---|---|---|---|---|
| 0 | iMeXx | 0.880 ± 0.033 | **0.846 ± 0.008** | 0.856 ± 0.011 |
| 1 | owline | 0.928 ± 0.042 | 0.898 ± 0.018 | **0.881 ± 0.014** |
| средн | | 0.904 | 0.872 (−3.6%) | **0.868 (−4.0%)** |

Вердикт гейта M2: улучшение fusion над растром **−4.0%** относительно —
порог −5% **не покрыт**, но направление корректно: гибрид лучше растра на
обоих фолдах, а на unseen-авторе (фолд 1) — лучший из трёх. На 2 авторах
такая разница статистически незначима; решение переносится на M0 (≥5–10
авторов). Чистый вектор уже сейчас не хуже гибрида при 5× меньшем размере —
если данные подтянутся, вариант C может остаться приоритетным.

## Веб-приложение jsnet (тренировка / сбор / статистика / распознавание)

`make up` поднимает сервер `jsnet/server/index.js` **фоном** (демоном, терминал
не занимает): адрес из `.env` (`WEB_HOST`/`WEB_PORT`, по умолчанию `127.0.0.1:3210`),
pid — `jsnet/logs/web.pid`, лог — `jsnet/logs/web.log`; рядом `make down` (остановить),
`make status`, `make log`. Сервер без внешних зависимостей (node:http +
node:sqlite), работает над той же базой `jsnet/db/app.db`, которую читает `make ds`:

- `/` — **вход по имени**: паролей и регистрации нет, имя и есть автор написаний
  (нового создаём сразу, `consent=1`; регистр не важен — `username` уникален без
  учёта регистра); подсказка — уже заведённые авторы (`/api/authors`);
- `/train.html` — **тренировка почерка**: калибровка эталонов символов
  (строчные, ЗАГЛАВНЫЕ, цифры 1–9) с гейтами мусора и модельной проверкой;
  спорные эталоны помечаются `qc` и попадают в очередь переписывания;
- `/collect.html` — **сбор датасета**: написание символов по заданию (2 на
  символ, 4 на путающие пары), буфер сессии в браузере, сдача в `train_samples`,
  выгрузка `inknet-collect/1`;
- `/stats.html` — **статистика датасета**: авторы, покрытие букв, спорные
  эталоны и готовность к `make ds` — посчитанные теми же гейтами билдера
  (`MIN_WRITER_CHARS`, `MIN_PTS`);
- `/lines.html` — **распознавание строк**: 1–3 строки
  подряд на холсте, CTC-модель `models/line_int8.onnx` считается в Web Worker
  (onnxruntime-web, WASM-only: на `http://IP` нет secure context — без WebGPU и
  Cache Storage), панель строк с инлайн-правкой и копированием. Воркер и
  препроцессинг — порт `line.worker.js`/`line-preprocess.js`/`ctc-decode.js`,
  контракты модели не тронуты (blank=0, `line_vocab.json[i-1]`, logits `[B,T,C]`).

Модельная QC написаний — без ONNX: ближайший сосед по `glyphEmbedding`
(`src/ink-features.js`, тот же код, что у билдера; описания эталонов считает
сервер, `/api/refs/emb`).

На тренировке и сборе — **настройки пера** (кнопка «✒ Перо»):
цвета/пресети, толщина пятна, вытянутость, угол, давление/наклон стилуса,
сглаживание, жёсткость краёв, «только перо» (palm rejection), клетка и пауза
автосохранения (`autoDelay`). `js/{pen,settings,pensettings,capture}.js` —
байтовые копии (синхронизируются `cp`, правки на месте не делать). Для датасета это безопасно: хранятся только векторы штрихов
(`xs/ys/dt`), а растр тройки рисуется фиксированным `PEN_DEFAULTS` на стороне
тренировки (правило паритета №5 не нарушается); на саму траекторию влияют лишь
сглаживание и palm rejection.

## Следующие шаги

1. Дождаться/перезапустить `make ablation` после M0 (≥5–10 авторов) — на 2
   авторах вердикт гейта M2 статистически незначим.
2. После гейта M2: экспорт `HybridNet` в ONNX (входы `image`+`feats`, цель —
   `export/`) и интеграция в веб-клиента (ассоциация штрихов с полосами в его
   `line-preprocess.js`, второй вход `line.worker.js`) — отдельным решением.
3. Деградация без векторного входа (в воркере штрихов может не быть) —
   отдельная проверка: пустой `feats` не должен ронять декодер.
