# inknet-hybrid

Проект **сбора написаний и датасетного конвейера**. Модель распознавания строк —
боевая растровая **`line_int8`** (обучение/дообучение/экспорт — в
[inknet-train](../inknet-train)). Векторная ветка штрихов и аблейшн-триада
(«Вариант B») **закрыты** по итогам эксперимента — см. «Направление закрыто».

## Что здесь живёт

| цель make | что делает |
|---|---|
| `make ds` | датасет `inknet-line-vectors/3` из снимка базы написаний `jsnet/db/app.db` (скрипт — байт-копия inknet-online, контроль `make parity`) |
| `make merge` | снимок базы `jsnet/db/app.db` → `data/db/app-merged.db` со склейкой логинов одного человека в одного автора (карта `scripts/writers-merge.json`) |
| `make ds-merged` | person-disjoint датасет из снимка → `data/line-vectors-m/` (фолды по людям); `make clean-merge` — удалить снимок |
| `make parity` | контроль синхронности билдера с inknet-online (на машине без соседнего репозитория — skip) |
| `make up` / `make down` | поднять / остановить веб-приложение jsnet **фоном** (демоном); `make status`, `make log` |
| `make deploy-*` | деплой веб-приложения на Ubuntu (systemd, nginx+TLS, перенос базы) — [docs/DEPLOY.md](docs/DEPLOY.md) |

Обучения здесь больше нет: python-код (`train.py`/`eval.py`/`compare.py`/
`hybridnet/`) удалён вместе с триадой. Растровые веса writer-disjoint бейзлайна
растра сохранены в `work-merged/raster/` — они нужны как точка сравнения при
дообучении `line_int8` (защита от забывания).

## Установка на чистой машине

Нужен Node ≥ 23 — веб-приложение jsnet работает на встроенном `node:sqlite`
без npm-зависимостей; скрипты датасета/merge тоже на node.

```bash
git clone <remote> inknet-hybrid && cd inknet-hybrid
cp .env.example .env   # правки не нужны для локального прогона; сервер — в .env.example
make ds-merged         # снимок базы + склейка людей + датасет по людям
make up                # веб-приложение: http://127.0.0.1:3210 (make down / status / log)
```

`make parity` на машине без `../inknet-online` печатает skip — гейт живёт там,
где есть оба репозитория.

## Person-disjoint разрез — как гонять

В `jsnet/db/app.db` у одного человека по несколько логинов (сдача с iPad и
Android-планшета в один день: `etel1`/`Etel2`, `Vika1`/`Vika2`, `Dima1`/`Dima2`),
а билдер группирует написания по `username` → writer-disjoint фолды пересекаются
по людям (протекали 6 фолдов из 8). Билдер править нельзя (гейт `make parity`),
поэтому логины склеиваются в **снимке** базы: `scripts/merge-writers.mjs` + карта
`scripts/writers-merge.json` (её правят люди, когда подтверждают, что аккаунты
принадлежат одному почерку). Исходная база не изменяется, `make parity` остаётся
зелёным.

```bash
make merge        # снимок app.db + склейка -> data/db/app-merged.db
make ds-merged    # датасет с фолдами по ЛЮДЯМ -> data/line-vectors-m/
```

`TEST_LINES=120` вместо 30: на 30 тестовых строках шум ±0.1 CER; синтез строк
бесплатный, дорожает только оценка. Цель `ds` (логин-разрез) при `.env` на
person-disjoint разрезе останавливает `guard-merged`: она собрала бы датасет по
ЛОГИНАМ поверх валидного. Обход осознанно — `FORCE_MERGED=1`. Разбор данных —
[docs/DATASET-AUDIT-2026-11-05.md](docs/DATASET-AUDIT-2026-11-05.md).

## Направление закрыто (2026-11, итог эксперимента «Вариант B»)

Гипотеза «векторная ветка штрихов поверх растра повышает распознавание»
**не подтверждена** на person-disjoint триаде (5 человек × 3 сида):
raster 0.454 / vector 0.575 / fusion 0.657 CER — растр лучший, гейт M2 (−5%)
не покрыт с большим запасом. Попытка выжать из вектора пер-user выгоду без
переобучения тоже закрыта: сетка α (взвешивание логитов растр+вектор,
`work-merged/` — удалена) дала α\* = 0 у всех авторов (CER при α\* точь-в-точь
растровая), oracle-α — сотые доли. Пробы вектора на уровне букв: кросс-авторский
NN top-1 0.40–0.44 при потолке внутри автора 0.55–0.63 — признаки не несут
«абсолютно точной» буквы. **`line_int8` — боевая и остаётся**; векторный код
(модели, обучение, экспорт, селектор гибрида в воркере) удалён из репозитория.

Дальнейшая работа по модели идёт в [inknet-train](../inknet-train):
дообучение `line_int8` на новых написаниях (`--refs app.db`, `--inbox`),
экспорт fp32 → int8 с проверкой паритета greedy. Сюда проект сводится к:
сбор написаний (jsnet), датасет/merge, доставка модели в веб-приложение
(`jsnet/public/models/line_int8.onnx` + `.ort`, правка `CACHE` в `sw.js`).

## Веб-приложение jsnet (тренировка / сбор / статистика / распознавание)

`make up` поднимает сервер `jsnet/server/index.js` **фоном** (демоном, терминал
не занимает): адрес из `.env` (`WEB_HOST`/`WEB_PORT`, по умолчанию `127.0.0.1:3210`),
pid — `jsnet/logs/web.pid`, лог — `jsnet/logs/web.log`; рядом `make down` (остановить),
`make status`, `make log`. Сервер без внешних зависимостей (node:http +
node:sqlite), работает над той же базой `jsnet/db/app.db`, которую читает `make ds`:

- `/` — **вход по имени**: паролей и регистрации нет, имя и есть автор написаний
  (нового создаём сразу, `consent=1`; регистр не важен — `username` уникален без
  учёта регистра); подсказка — уже заведённые авторы (`/api/authors`);
- `/train.html` — **тренировка почерка**: калибровка эталонов символов
  (строчные, ЗАГЛАВНЫЕ, цифры 1–9) с гейтами мусора и модельной проверкой;
  спорные эталоны помечаются `qc` и попадают в очередь переписывания;
- `/collect.html` — **сбор датасета**: написание символов по заданию (2 на
  символ, 4 на путающие пары), буфер сессии в браузере, сдача в `train_samples`,
  выгрузка `inknet-collect/1`;
- `/stats.html` — **статистика датасета**: авторы, покрытие букв, спорные
  эталоны и готовность к `make ds` — посчитанные теми же гейтами билдера
  (`MIN_WRITER_CHARS`, `MIN_PTS`);
- `/lines.html` — **распознавание строк**: 1–3 строки
  подряд на холсте, CTC-модель считается в Web Worker
  (onnxruntime-web, WASM-only: на `http://IP` нет secure context — без WebGPU и
  Cache Storage), панель строк с инлайн-правкой и копированием. Модель —
  боевая растровая `models/line_int8.onnx` (+ предоптимизированный `.ort`).
  Воркер и препроцессинг — порт `line.worker.js`/`line-preprocess.js`/`ctc-decode.js`,
  контракты модели не тронуты (blank=0, `line_vocab.json[i-1]`, logits `[B,T,C]`).

  Распознавание — **полностью на устройстве** (архитектурное решение): сервер в
  инференсе не участвует, только отдаёт статику (модель кэшируется service
  worker'ом cache-first — после первого визита страница распознавания работает
  офлайн) и принимает данные (`/api/*` — всегда живая сеть). Серверного API
  распознавания не будет.

Модельная QC написаний — без ONNX: ближайший сосед по `glyphEmbedding`
(`src/ink-features.js`, тот же код, что у билдера; описания эталонов считает
сервер, `/api/refs/emb`).

На тренировке и сборе — **настройки пера** (кнопка «✒ Перо»):
цвета/пресети, толщина пятна, вытянутость, угол, давление/наклон стилуса,
сглаживание, жёсткость краёв, «только перо» (palm rejection), клетка и пауза
автосохранения (`autoDelay`). `js/{pen,settings,pensettings,capture}.js` —
байтовые копии (синхронизируются `cp`, правки на месте не делать). Для датасета это безопасно: хранятся только векторы штрихов
(`xs/ys/dt`), а растр датасета рисуется фиксированным `PEN_DEFAULTS` на стороне
тренировки; на саму траекторию влияют лишь сглаживание и palm rejection.

## Следующие шаги

1. Накапливать написания (сбор новых авторов через jsnet) — объём данных
   сейчас главный ограничитель: разброс CER ±0.15 на прогон.
2. Дообучение `line_int8` на новых данных — в `../inknet-train`
   (`--init work/model-best.pt --lr 1e-4`, контроль CER по своим авторам на
   забывание; экспорт fp32 → int8, паритет greedy).
3. После нового экспорта — доставка в веб-приложение: `jsnet/public/models/`
   (`line_int8.onnx` + `.ort`) и `CACHE` в `jsnet/public/sw.js`.
